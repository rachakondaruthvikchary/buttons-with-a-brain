Motion design notes

Every transition in this component is intentional. Nothing animates just because it can — each duration and easing curve is chosen to match what the state change is communicating.

Interaction Duration Easing Why
Hover / focus 180ms ease-out Fast enough to feel responsive to a pointer, never sluggish.
State transition (idle↔loading↔success/error) 280–320ms cubic-bezier(0.16, 1, 0.3, 1) Long enough to register as a meaningful change, short enough to stay snappy. The curve overshoots slightly on entry so new states feel like they "arrive," not just appear.
Success feedback 320ms draw + 1.6s hold ease-out The checkmark draws itself in once, quickly, then the state holds briefly so the win registers before auto-returning to idle.
Error feedback 400ms shake ease-in-out (oscillating) A short, low-amplitude shake reads as "something's wrong" without feeling like a punishment. Error styling then holds indefinitely until retried.

All animated properties are transform and opacity only — no layout-triggering properties (width, height, top, left, margin) are animated, so every transition stays on the compositor thread. Every state change also has a non-motion signal (color, icon, text) so the interface reads correctly with prefers-reduced-motion enabled.
